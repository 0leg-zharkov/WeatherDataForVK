# Weather Data for VK

Консольное приложение на C# для получения текущей температуры и страны по списку городов через публичный API [wttr.in](https://wttr.in).

## Что делает

1. Загружает список городов из файла `cities.txt`
2. Для каждого города получает данные через API `https://wttr.in/{city}?format=j1`
3. Создаёт модель `WeatherData` с полями: **Город**, **Текущая температура в °C**, **Страна**
4. Выводит информацию по каждому городу: `Tokyo, Japan +18 °C`
5. Группирует города по странам и выводит статистику:
    - Количество городов
    - Средняя температура
    - Минимальная температура
    - Максимальная температура

## Почему так сделано

- **Разделение на провайдеры (`IWeatherProvider`)** - потому что "правильный" путь через `HttpClient` в моей сети не работает. Провайдер с DPI рвёт длинные HTTPS-сессии к `wttr.in` - сервер успевает отдать только первые ~15–21 КБ, а `HttpClient` дожидается полного ответа и падает по таймауту. Пришлось сделать резервный транспорт через `curl.exe`, а общий интерфейс помог не растаскивать логику по всему коду.

- **Прогревочный запрос при старте** - чтобы не тратить по 15 секунд на каждый город, если `HttpClient` в текущей сети вообще не проходит. Один раз проверяем - и дальше идём тем путём, который реально работает.

- **`curl.exe` с флагом `--ssl-no-revoke`** - помимо DPI, Windows отказывалась устанавливать TLS-соединение из-за невозможности проверить отзыв сертификата. Флаг отключает эту проверку и позволяет curl установить соединение.

- **Короткий таймаут в curl (`--max-time 8`)** - установил, что соединение всё равно оборвётся на ~20 КБ. Этих килобайт достаточно: поля `temp_C` и `country` лежат в первых ~1.3 КБ ответа. Ждать больше смысла нет.

- **Парсер работает и с обрезанным JSON** - curl отдаёт частичный ответ. Сначала пробуется `JsonDocument.Parse` (нормальный путь), а в `JsonException` происходит переключение на регулярки, которые вытаскивают нужные поля из неполного json.
